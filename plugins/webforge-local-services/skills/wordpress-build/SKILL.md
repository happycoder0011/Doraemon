# /webforge-local-services:wordpress-build — WordPress scaffold

Run when the operator invokes `/webforge-local-services:wordpress-build <client-slug>` and `project.type = local-services`, `cms = wordpress`, `template = wordpress-theme`.

## Pre-flight checks

1. `projects/<slug>/project.config.yaml` exists and validates:
   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/../webforge-core/scripts/validate_config.py \
     projects/<slug>/project.config.yaml
   ```
2. `projects/<slug>/strategy/keywords.json` exists (Strategy phase must be complete).
3. `infrastructure.deployment_target` is `wp-hosting` or `aws`.
4. SSH / WP-CLI access to the target host (Kinsta, WP Engine, etc.) — surface as a pre-flight question if not.

If any check fails, **stop** and surface the issue.

## Build steps

### 1. Snapshot the host (one-time, before any changes)

```bash
# Kinsta example — adjust for your host
ssh <host> "cd ~/public && wp db export ~/snapshots/before-build-$(date +%Y%m%d).sql"
```

Record the snapshot path in `projects/<slug>/build/SNAPSHOTS.md`. If anything goes wrong, this is the rollback.

### 2. Install WordPress (if not present)

Most managed WP hosts already have WP installed. If the host is bare:

```bash
ssh <host> "cd ~ && wp core download --version=latest"
```

### 3. Install theme

Pick from: GeneratePress, Kadence, or a custom block theme. Justify in the changelog.

```bash
ssh <host> "wp theme install generatepress --activate"
```

### 4. Install required plugins

Always install:

```bash
ssh <host> "wp plugin install rank-math seo --activate"
ssh <host> "wp plugin install wpforms-lite --activate"
ssh <host> "wp plugin install wp-smushit --activate"
ssh <host> "wp plugin install limit-login-attempts-reloaded --activate"
ssh <host> "wp plugin install updraftplus --activate"
```

Justify each. For local-services specifically:
- **Rank Math SEO** (or Yoast) — schema markup + sitemap
- **WPForms** (or Gravity Forms) — contact / quote forms
- **WP Super Cache** or the host's caching plugin — performance

### 5. Configure Rank Math

```bash
ssh <host> "wp rank-math option update general jsonld_on 1"
ssh <host> "wp rank-math option update general sitemap_on 1"
```

Connect to Google Search Console via the connection wizard — surface the URL for operator to complete the OAuth.

### 6. Generate pages

For each page in `deliverables.website.pages`:

```bash
ssh <host> "wp post create --post_type=page --post_status=draft \
  --post_title='<title>' --post_content='<content>'"
```

Page content is generated by the **webforge-local-services-frontend-eng** agent (delegated). This skill handles the WP-CLI plumbing.

### 7. Inject schema markup

For each page, inject the JSON-LD declared in `strategy/keywords.json.schema_inventory`. Use a custom Rank Math hook or a child theme function.

### 8. Site settings

```bash
ssh <host> "wp option update blogdescription '<from intake.json>'"
ssh <host> "wp option update siteicon"
ssh <host> "wp option update timezone_string '<from infrastructure.geo>'"
```

### 9. Write the changelog

Append to `projects/<slug>/build/CHANGELOG.md`:

```
## <date> — WebForge wordpress-build v1.0

Installed theme: <choice>
Installed plugins: <list>
Pages scaffolded: <count>
Schema types wired: <count>
Cost to scaffold: ~$0.10 of compute.
Reversible: snapshot at <path>.
```

Update `state.json` with `phase: build`, `last_step: wordpress-build`, `confidence: 0.85`.

## Rollback

```bash
ssh <host> "wp db import ~/snapshots/before-build-<date>.sql"
```

Then drop the new pages / revert the theme.

## What you must NOT do

- Skip the snapshot. Host snapshots are how you recover when WP-CLI commands go sideways.
- Edit plugins or theme files directly. Use WP-CLI or the host's Git deployment.
- Run `wp plugin deactivate --all` "to debug". Disable one plugin at a time.
- Promote to production before the seo-tech audit pass.

## Required MCP / CLI

This skill requires either:
- The WordPress MCP server (`mcp__wordpress__*`), OR
- `wp` CLI + SSH access to the host

If neither, stop and surface:
> "I can't reach WordPress — neither the MCP nor WP-CLI is set up. Install WP-CLI on your machine and provide host SSH details, or add the WordPress MCP, then retry."

## Hand-off

When the build is complete, hand off to:
- **webforge-local-services-seo-tech** for schema + performance audit.
- **webforge-local-services:kinsta-deploy** for production deploy.
